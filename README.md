# ESP8266 Smart Weather Station & Universal IR Remote Hub

This repository contains the code and wiring for a small ESP8266-based device that combines a weather/NTP display with a simple universal IR learning/transmit hub. I wrote this project to learn more about precise IR timing on the ESP8266 and to experiment with a small touchscreen HMI.

This README is a concise, hands-on record of what I built, how I built it, and how to run it — written by me (no AI boilerplate).

## What I built
- A 2.4" TFT display (ILI9341) touchscreen UI that shows a clock and weather data.
- An IR learning mode that records remote signals and saves them to SPIFFS.
- An IR transmit mode that replays saved signals through an IR LED driven by a 2N2222 transistor.
- A simple strategy to pause network activity during IR capture so the decoder sees stable timing.

## Why this approach
IR decoding on ESP8266 is sensitive to timing jitter. The Wi‑Fi stack and other background tasks can introduce interrupts that break microsecond-level timing. To get reliable captures I disable or pause Wi‑Fi activity briefly while sampling the TSOP output and recording pulse timings. This is a deliberate tradeoff: captures need accuracy, and brief pauses (seconds or less) are acceptable for a local device.

## How I implemented it (high level)
- UI: TFT_eSPI library for the ILI9341 display and a simple touch keyboard I implemented for naming signals.
- Storage: SPIFFS to store touch calibration and learned IR sequences so they persist across reboots.
- IR handling: An interrupt-driven pulse-timing capture routine records highs/lows in microseconds, then the code tries to match/normalize the pattern and save it alongside a user-provided name.
- IR transmit: The stored timing sequence is replayed using the IR LED and a 38 kHz carrier generated by a hardware or software PWM method depending on reliability.
- Network: OpenWeatherMap API for weather data and NTP for time sync. Weather updates are intentionally infrequent (default: 10 minutes) to reduce network use.

## Hardware (wiring notes)
I used a 2N2222 NPN transistor to drive the IR LED from the 3.3V rail. This protects the ESP8266 GPIO from the LED's current draw.
- IR LED anode -> 3.3V
- IR LED cathode -> 2N2222 collector
- 2N2222 emitter -> GND
- 220 Ω resistor between ESP8266 GPIO and 2N2222 base (D1 / GPIO5)
- TSOP (IR receiver) data out -> D4 (GPIO2)

Display SPI pins (as wired in my build):

| Component | ESP8266 Pin |
| --------- | ----------- |
| VCC / LED | 3V3         |
| CS        | D8 (GPIO015) |
| DC/RS     | D3 (GPIO00)  |
| MOSI      | D7 (GPIO013) |
| SCK       | D5 (GPIO014) |
| GND       | GND         |

Adjust pins in the code if your board layout differs.

## Quick start
1. Wire the display, TSOP, IR LED/2N2222, and power according to the pinout above.
2. Edit the credentials section in the code to add your Wi‑Fi SSID, password, and OpenWeatherMap API key.
3. Flash the firmware to the ESP8266 (Arduino IDE or PlatformIO). The touchscreen calibrator runs on first boot and stores values in `/touch.cal` on SPIFFS.
4. Use the touchscreen to switch to "IR Learn", press a remote button near the receiver, give it a name, and save. Then go to "Transmit" to replay it.

## Usage notes and tips
- If captures are inconsistent: move the remote closer to the TSOP, avoid direct sunlight or strong IR sources, and ensure the Wi‑Fi pause is occurring during capture.
- If transmit range is low: check transistor wiring, base resistor value, and LED polarity.
- Touch calibration: delete `/touch.cal` and reboot to re-run calibration.

## Troubleshooting
- Weather not updating: check Wi‑Fi credentials and API key; use serial output to see HTTP/NTP errors.
- IR capture shows garbage: confirm TSOP orientation and ensure the Wi‑Fi pause code runs before capturing.

## Where I worked and what I learned
I focused on a reliable IR capture flow and a minimal, usable UI. Key lessons:
- Pausing or disabling Wi‑Fi briefly can make IR decoding far more reliable on ESP8266.
- SPIFFS is convenient for small persistent data like calibration and learned signals.
- Balancing UI responsiveness with timing-critical tasks is the main challenge on a single-core microcontroller.
